# 设计说明

## 为什么全部美术都用代码绘制

外部图片素材既带来版权风险，也让「原创」难以自证。本项目把每个角色与场景元素写成
绘制函数（`TuanziArt` / `WorldArt`），由椭圆、多边形与线段组合而成：

- 椭圆用「变换缩放 + 画圆」实现，保证描边在任何比例下都圆滑（`TuanziArt.ellipse`）。
- 团子由 6 层构成：落地阴影 → 双脚 → 身体与高光 → 五官 → 头顶嫩芽 → 小手，
  全部读取同一个状态字典（呼吸相位、步伐、眨眼、张嘴、朝向、受击、配色）。
- 同一个 `draw_tuanzi` 同时服务于玩家、NPC、战斗单位与图鉴头像，
  靠 `scale`/`facing`/`body` 等参数区分，避免多套美术不一致。

## 战斗站位与景深

敌方在后（y=452、缩放 1.0），我方在前（y=604、缩放 1.28），各站在一个椭圆台座上；
先画远端再画近端，保证遮挡关系正确。伤害公式：

```
基础 = 技能威力 + 攻击 × 1.25 + 等级 × 0.9 − 防御 × 0.85
伤害 = max(4, 基础) × (0.88 + rand × 0.24)
```

下限 4 保证任何攻击都有意义；随机浮动让同一招有观感差异。
出手顺序按速度降序，每回合双方各行动一次；`MAX_ROUNDS = 60` 防止双方互奶进入无限回合。

## 存档为什么不用 user://

部分受限环境下系统用户目录不可写，`user://` 会静默失败，导致玩家「存了却没存上」。
`SavePaths` 因此真实写入探针文件来检测可写性，按 便携目录 → 系统目录 → 临时目录 顺序回退。
导出后优先写在 exe 同目录，整个文件夹拷走即可带走存档。

## 已知取舍

- 没有寻路，障碍采用椭圆推出（`_resolve_obstacles`），简单且开销低。
- 未做道具在战斗中的实际使用，背包目前只有展示与图鉴联动。
- 无音频：避免引入来源不明的音效资源，后续可用程序化合成补齐。
